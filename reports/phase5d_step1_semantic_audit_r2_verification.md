## 3. 핵심 모순

### V-01 — 모바일 가시성 assertion이 잘못됨

시나리오 G의 `peekVisibleOk`는 높이가 0보다 큰지만 검사한다.

```text
height = 43px
top = 845px
viewport height = 844px
```

요소 크기는 존재하지만 화면 아래에 있으므로 사용자에게 보이지 않는다. 원시 JSON의 엄격 가시성 함수는 이를 정확히 `false`로 판정했지만, 최종 assertion과 보고서는 PASS로 처리했다.

### V-02 — 모바일 확장 상태가 화면에 나타나지 않음

클래스 `mobile-expanded` 존재만 확인했으며 패널 자체의 뷰포트 교차를 완료 조건에 넣지 않았다. 결과적으로 히어로 콘텐츠가 `top: 924px`에서 시작해 844px 화면 밖에 있다.

### V-03 — 브랜드 동시 노출이 입증되지 않음

원시 JSON에서 브랜드 행은 `isActuallyVisible: true`로 기록됐지만 FTC 히어로는 `false`다. 또한 PNG에는 메가MGC커피 행이 보이지 않는다. overflow/clipping ancestor를 가시성 함수가 검사하지 않아 브랜드 행의 실제 노출도 신뢰할 수 없다.

### V-04 — 보고서의 완료 선언이 원시 데이터와 불일치

- 보고서: `실제 가시성 판정 PASS`, `숨겨진 DOM 측정 0건`
- 원시 JSON: C의 FTC 히어로, E/G의 피크 바, F의 히어로·푸터가 `isActuallyVisible: false`

따라서 보고서 판정은 원시 데이터에 맞게 정정되어야 한다.

## 4. 유효하게 확인된 제품 결함

이번 감사 실패와 별개로 다음 제품 결함은 실제 화면 및 코드 구조상 유효하다.

1. 데스크톱 FTC 패널에 `특정 브랜드 실적 아님` 문구가 없다.
2. 지역 선택 상태에서 히어로 라벨에 `전국` 범위가 직접 표시되지 않는다.
3. 2026 스냅샷의 결손·직접 비교 불가 안내가 작은 각주와 툴팁에 의존한다.
4. 모바일 FTC 피크/확장 패널이 390×844 화면 밖에 배치되는 별도의 레이아웃 결함 가능성이 확인됐다.

## 5. 다음 재검증 지침

1. 애플리케이션 코드는 아직 수정하지 않는다.
2. 감사 스크립트의 모바일 assertion을 `inspectVisibility(...).isActuallyVisible === true`로 변경한다.
3. 확장 상태에서는 패널, 헤더 또는 히어로 중 최소 하나가 실제 뷰포트와 교차하는지 assertion한다.
4. 가시성 함수에 모든 overflow clipping 조상과 실질적 가림 여부를 추가한다.
5. 시나리오 C는 브랜드 행과 FTC 히어로가 모두 `isActuallyVisible: true`일 때만 캡처한다.
6. 모바일 캡처에서 피크 또는 확장 패널이 눈으로 식별되지 않으면 PASS로 기록하지 않는다.
7. 현 상태에서 요소가 계속 화면 밖이라면 감사 실패가 아니라 **제품 레이아웃 결함**으로 확정하고 Step 5D-2 수정 대상으로 보고한다.
8. 사용자 시험 없이 오인 확률이나 사용자 행동 비율을 수치로 단정하지 않는다.
