### 2.1 4개년 전수 대사 검증 규칙
1. **모수 보존 법칙**: `양수 매출 표본 + 0원 매출 표본 + 결측(NULL) 표본 = 전체 브랜드 표본` (32개 조합 전수 일치).

## 4. API 성능 실측 (캐시 적중·미적중 정격 분리 및 규격 정정)

### 4.1 측정 조건 및 엄격한 판정 원칙 (Measurement Conditions & Strict Rules)
- **호스트 및 환경**: `127.0.0.1:8000` (Localhost Loopback, Uvicorn 0.30+ Single Worker, Windows 11 Home x64, Python 3.14 `urllib.request`)
- **데이터베이스 연결**: SQLite 3 WAL Mode (`data/ftc_macro_statistics_v1.sqlite3`, `mode=ro` 읽기 전용 URI 연결)
- **캐시 적중 (Warm Cache Hit) 측정 조건**:
  - 동일 파라미터로 **연속 30회 호출 ($N=30$)**을 수행하여 In-Memory `_CACHE_STORE` 적중을 보장함.
  - Mean, Median, Min, Max, Stdev 및 **통계적으로 유효한 95 백분위수(p95)**를 실측 산출함.
  - 판정 기준: p95 지연시간 50ms 미만 $\rightarrow$ **PASS**.
- **캐시 미적중 (Cold Cache Miss)의 검증 한계 및 판정**:
  - **헤더 부재**: 백엔드 API 응답 헤더에 캐시 적중/미적중 식별자(`X-Cache: HIT/MISS` 등)가 제공되지 않으며, 외부 HTTP 클라이언트에서 서버 메모리를 독립 초기화하는 관리 API가 없어 실제 미적중 여부를 객관적으로 입증할 수 없음.
  - **단일 엔드포인트 N=1의 통계적 불가성**: `/status`, `/years`, `/analytics/summary`, `/spatial/density/grid`, `/spatial/hotspots`의 1회 측정값($N=1$)은 표본수가 1개이므로 **p95 백분위수를 산출하는 것이 수학적으로 불가능함**. 따라서 p95 표기를 전면 배제하고 단순 1회 호출 참고치로만 기재함.
  - **8개 업종 최초 호출의 추정성**: 벤치마크 및 시계열 API의 8개 업종 최초 1회 호출($N=8$) 역시 캐시 상태 식별 헤더가 없어 '미적중으로 추정되는 참고치'에 불과함.
  - **최종 판정**: 캐시 미적중(Cold) 성능 검증 목표는 **[미검증 (UNVERIFIED)]**으로 정식 분류함.
- **HTTP Content-Encoding 전송 실측치 및 정정**:
  - `Accept-Encoding: gzip` 요청 시 응답 헤더에 `Content-Encoding`이 반환되지 않음을 확인(**비압축 원시 JSON 전송**).
  - 로컬 개발 환경 uvicorn에는 `GZipMiddleware`가 설치되지 않아 압축이 발생하지 않음.
  - 따라서 종전의 Gzip 수치는 **"Python `gzip.compress()` 로컬 연산 기준 압축 추정 크기 (실제 전송은 비압축 원본 JSON)"**으로 투명하게 정정 표기함.
