# Phase 6 3D GIS MVP 실행 계획서 (R1)

- 작성일: 2026-10-20
- 선행 승인: Phase 5D 완료 결과 사용자 승인
- 현재 상태: 계획 승인 대기 — 제품 코드/API/DB 변경 없음
- 목표: 기존 MapLibre 기반 3D 지도를 재사용하여 줌인 개별 점포 탐색을 완성하고, 외부 3D 건물 데이터는 출처·라이선스·비용 검증 후 별도 승인으로 격리한다.

## 1. 현재 구현과 실제 공백

| 영역 | 현재 상태 | Phase 6 판단 |
|---|---|---|
| 100m 밀집도 3D 격자 | `MapContainer.jsx`의 MapLibre `fill-extrusion`으로 구현 완료 | 재구현하지 않음 |
| 2D/3D 시점 전환 | Pitch/Bearing 전환 및 리사이즈 보존 검증 완료 | 재사용 |
| 핫스팟 카메라 이동 | API의 pitch/bearing/zoom과 `flyTo` 연동 완료 | 재사용 |
| 개별 점포 API | `/api/v1/spatial/stores/bbox`, `/stores/{bizes_id}` 구현 완료 | 프론트엔드 연동 필요 |
| 개별 점포 지도 레이어 | 프론트엔드 서비스와 지도 레이어 없음 | Phase 6 MVP 핵심 구현 |
| 3D 건물 | 현재 베이스맵은 OSM 래스터이며 건물 높이 벡터 소스 없음 | 외부 데이터 승인 전 구현 금지 |
| deck.gl | 패키지 미설치, 현재 핵심 3D 표현은 MapLibre만으로 동작 | MVP에는 추가하지 않음 |

## 2. 설계 원칙

1. **최소 변경**: 기존 MapLibre 지도와 FastAPI 공간 API를 사용한다. 동일 기능을 위해 Three.js 렌더러나 deck.gl을 중복 도입하지 않는다.
2. **줌 기반 LOD**:
   - 줌 `< 10.5`: 지역 중심 시점만 표시
   - 줌 `10.5~13.99`: 100m 밀집도 격자
   - 줌 `>= 14`: 현재 뷰포트의 개별 점포 최대 500개
3. **데이터 의미 보존**: 브랜드 공식성, 매칭 신뢰도, 운영 형태, 업종 확정 상태를 합치지 않고 API의 4축 값을 그대로 표시한다.
4. **요청 안전성**: 지도 이동 종료 시에만 BBOX를 조회하고, 이전 요청은 `AbortController`로 취소한다. 화면 밖 응답과 오래된 응답은 폐기한다.
5. **성능 합격선**: 목표 60fps, 승인 기준은 기존 확정값인 데스크톱 45fps 이상·모바일 30fps 이상으로 통일한다.
6. **외부 공간 데이터 격리**: 건물·지형 데이터는 출처, 좌표 정합성, 라이선스, 타일 비용을 검증하고 사용자가 승인하기 전 제품에 연결하지 않는다.

## 3. 단계별 실행 계획

### Step 6-1 — 개별 점포 줌인 MVP

목표는 이미 존재하는 BBOX API를 지도에 연결하여 줌 14 이상에서 점포를 탐색하고 상세 정보를 확인하는 것이다.

예상 변경 범위:

- `frontend/src/services/api.js`
  - `fetchStoresByBbox(...)`, `fetchStoreDetail(...)` 추가
- `frontend/src/components/MapContainer.jsx`
  - MapLibre GeoJSON 점포 소스와 `circle` 레이어 추가
  - `moveend` 기반 BBOX 조회, 요청 취소, 줌 LOD, 선택/호버 처리
  - 점포 클릭 시 상세 API를 호출하고 기존 안전한 DOM 생성 방식으로 팝업 표시
- `frontend/src/App.jsx`
  - 새 전역 상태는 만들지 않고 현재 지역·업종 선택값만 MapContainer에 전달
- 검증 스크립트 1개와 JSON/PNG 증빙

표현 계약:

- `FRANCHISE_CONFIRMED`: Emerald
- `BRAND_CONFIRMED`: Blue
- `UNVERIFIED`: Amber
- `UNMATCHED`: Slate
- 팝업에서 `brand_officiality`, `match_status`, `operation_type`, `classification_status`를 별도 라벨로 표시
- `is_multi_brand_store=1`이면 보조 브랜드 경고 표시
- 데이터가 없는 상태, API 오류, 500개 제한 도달 상태를 서로 구분

완료 조건:

- 줌 14 미만에서는 점포 요청과 점포 레이어가 비활성
- 줌 14 이상에서 요청 BBOX와 실제 지도 bounds 일치
- 빠른 이동 시 마지막 뷰포트 응답만 렌더링
- API 수신 피처 수와 MapLibre 소스 피처 수 일치
- 실제 점포 클릭으로 상세 팝업 개방, 4축 의미와 복수 브랜드 경고 정확
- 지역·업종 필터 및 기존 격자/핫스팟/FTC 패널 회귀 없음

### Step 6-2 — 레이어 제어와 카메라 사용성 정리

Step 6-1 승인 후에만 진행한다.

- 기존 `SlimMapRail`을 확장해 `3D 격자`, `개별 점포`, `핫스팟` 표시 상태를 제어
- 기존 2D/3D 토글과 중복되는 새 컨트롤은 만들지 않음
- 점포 레이어 기본값은 줌 조건에 따른 자동 표시, 사용자가 끄면 현재 세션 동안 유지
- 카메라 자동 회전은 분석 정확도에 기여하지 않으므로 MVP에서 제외

완료 조건:

- 키보드와 44px 이상 터치 타깃으로 모든 레이어 제어 가능
- `aria-pressed`/명확한 한글 라벨 제공
- 모바일 390×844에서 지도 중심 차폐와 가로 오버플로 0px
- `prefers-reduced-motion`에서 카메라 이동 시간 최소화

### Step 6-3 — 3D 건물 데이터 타당성 검증 (코드 구현 전 게이트)

이 단계는 제품 구현이 아니라 외부 데이터 도입 의사결정 문서 작성 단계다.

검증 후보:

- Overture Maps Buildings
- 국내 공공 건축물 공간정보 또는 허가된 벡터 타일 공급원

필수 검증:

1. 대한민국 커버리지와 건물 높이/층수 결측률
2. WGS84 변환 및 점포 좌표와의 공간 정합성
3. 라이선스 귀속·재배포·파생 데이터 공개 의무
4. 타일 생성/호스팅 비용과 오프라인 개발 가능성
5. 광진구·강남구·제주시 표본에서 건물 수, 높이 결측, 시각 오차
6. 모바일 GPU 부하와 점포/격자 동시 표시 성능

승인 결과는 다음 중 하나로 고정한다.

- `ADOPT`: 출처와 운영비가 확정되어 Step 6-4 구현 가능
- `HOLD`: 품질 또는 비용 보완 후 재검토
- `REJECT`: Phase 6에서는 건물 레이어 제외

### Step 6-4 — 승인된 경우에만 3D 건물 구현 및 최종 회귀

- Step 6-3이 `ADOPT`일 때만 착수
- MapLibre 벡터 소스의 `fill-extrusion`을 우선 사용
- 높이 결측 건물은 실측 높이로 오인되지 않도록 별도 기본값/범례 표기
- 실제 입면·창문 텍스처·그림자 시뮬레이션은 별도 요구가 없으므로 제외
- 격자, 점포, 건물의 동시 표시에서 깊이 충돌과 클릭 우선순위를 검증

최종 완료 조건:

- 데스크톱 1440×900에서 평균 45fps 이상
- 모바일 390×844에서 평균 30fps 이상
- 점포 BBOX API 응답 및 렌더링 피처 수 정합
- 키보드, 실제 터치, 팝업 뷰포트 안착, 모션 축소 전수 통과
- 프로덕션 빌드 성공
- 보호 파일 3종 SHA-256 불변

## 5. 영향 범위와 보호 범위
